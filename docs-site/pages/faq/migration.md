# 迁移与兼容

## 从彩虹 DNS 迁入

彩虹 DNS Pro 保持与彩虹 DNS 兼容的表结构，可以直接绑定现有 MySQL 数据库。

步骤：

1. 停止或冻结旧站写入。
2. 备份旧数据库。
3. 部署彩虹 DNS Pro。
4. 打开安装页，选择 MySQL。
5. 填写旧数据库连接信息。
6. 表前缀填写旧站实际前缀，默认 `dnsmgr_`。
7. 点击“测试数据库连接”。
8. 检测到已有数据后执行绑定。
9. 应用重启后使用原管理员账号登录。

系统不会删除或覆盖原有域名、用户、解析、证书与任务数据。

## 旧版 API 兼容

数据表兼容不代表 HTTP API 兼容。旧版彩虹 DNS 客户端使用 `/api/domain`、`/api/record/*` 等表单签名接口，新版默认使用 `/api/v1` 的 RESTful JSON 接口。

如果旧客户端暂时不能改造，可在“系统设置 → 旧版接口兼容”中开启兼容层。兼容层默认关闭，使用旧版 `apikey` 与 MD5 签名，详细说明见 [旧版彩虹 DNS API 兼容](/api/legacy)。

## 旧站仍在运行

不要同时让旧站和新站写同一个数据库。旧站继续写可能造成缓存、任务与状态冲突。迁移后建议停用旧站。

## 从备份迁入

1. 新环境完成初始化安装。
2. 在安装成功页选择“导入已有备份”。
3. 整站归档填写备份密钥。
4. 口令归档填写备份口令。
5. 导入完成后应用重启。
6. 使用备份中的管理员账号登录。

也可以在新站登录后从“备份与恢复”导入，但安装时导入更直接。

## MySQL 与 SQLite 切换

不推荐直接复制数据库文件跨类型迁移。使用整站备份在不同数据库之间导入导出。

迁移顺序：

1. 从源站导出整站备份。
2. 新站选择目标数据库类型并安装。
3. 导入备份。
4. 检查用户、域名、账户、证书与任务。

## 升级兼容

首次启动会自动迁移。已有 `config.json` 没有 `db_type` 字段时按 MySQL 继续运行，不会自动切换数据库。

升级前务必做整站备份。回滚时如果新版本已执行不兼容迁移，需要恢复备份。

## 域名与 CDN 迁移

- DNS 域名需要重新导入到新站。
- CDN 加速域名可以同步云端已有资源。
- 证书订单可以随整站备份恢复。
- 自动部署任务恢复后确认目标账户仍可用。
- 容灾与定时任务恢复后确认记录 ID 与账户权限。

## 迁移后检查

1. 登录与 TOTP。
2. 域名与解析记录数量。
3. DNS 账户验证。
4. CDN 域名与 CNAME。
5. 证书到期时间与自动续签。
6. 部署任务目标。
7. 备份计划与密钥。
8. 通知通道。
9. API Key 与旧版密钥。
10. 调度器运行状态。

## 常见问题

### 绑定后看不到域名

确认表前缀正确。旧站自定义过前缀时，必须填写实际值。

### 原管理员无法登录

确认绑定的是原数据库。也可以在安装页为已有数据库补建管理员，系统会保留原数据并新增管理员。

### 迁移后任务报错

账户凭证可能因系统密钥不同无法解密。重新填写账户凭证后保存。

### 备份密钥丢失

整站归档无法恢复。请从密码管理器或外部密钥系统找回旧密钥。
