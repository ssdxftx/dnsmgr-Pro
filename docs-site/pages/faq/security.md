# 安全加固

## 账号

- 管理员使用强密码，并开启 TOTP。
- 不同管理员使用独立账号。
- 禁止共享超级管理员账号。
- 定期检查用户列表与封禁状态。
- 离职或项目结束时及时删除账号并吊销 API Key。

## API Key

- 为每个脚本或系统创建独立 Key。
- 使用最小作用域。
- 设置到期时间。
- 配置 IP 白名单。
- 定期轮换。
- 发现泄露立即吊销并检查审计日志。
- 停用旧版单密钥。

## 反向代理

- 生产环境启用 HTTPS。
- 设置 `DNSMGR_TRUST_PROXY` 为具体代理 IP 或网段。
- 只允许可信来源跨域。
- 不要关闭 HSTS，除非有明确原因。
- 限制管理后台来源 IP。
- 代理层不要缓存 `/api/*`。

## 部署命令

部署自定义命令默认禁用。需要时同时配置：

```bash
DNSMGR_ALLOW_DEPLOY_CMD=1
DNSMGR_DEPLOY_CMD_ALLOWLIST=systemctl reload nginx,docker restart
```

白名单按前缀匹配，命令不经过 shell。不要把任意 shell 解释器加入白名单。

## 数据库

- 使用独立数据库账号，只授权目标库。
- 不要使用 root 连接应用。
- 限制数据库网络访问来源。
- 定期备份。
- MySQL 与 SQLite 备份都通过整站归档完成。

## 数据目录

- 挂载持久化卷。
- 目录所有者设置为 `1000:1000`。
- 限制宿主机目录权限。
- 不要把数据目录暴露为静态网站。
- 定期检查磁盘空间。

## 备份密钥

- 整站备份密钥离线保存。
- 使用 `DNSMGR_BACKUP_KEY` 时不要把值写入镜像或公开配置。
- 轮换前确认旧备份仍可恢复。
- 备份文件按敏感数据管理。

## 私有凭证

- 敏感云账户使用口令模式保险库。
- 口令与登录密码不同。
- 恢复码离线保存。
- 必要时开启“不参与整站备份”。

## 网络访问

应用会校验监控目标、Webhook、部署目标与备份远端的地址，降低 SSRF 风险。仍建议：

- 限制应用所在网络的出站访问。
- 不把管理后台直接暴露到公网。
- 对 Webhook 目标使用域名白名单。
- 定期检查异常出站连接。

## 日志与审计

- 开启审计并设置合理保留天数。
- 定期导出审计日志。
- 关注失败登录、API Key 创建与吊销、部署执行、备份恢复。
- 不要记录密码、私钥或完整 Token。

## 容器

- 使用非 root 用户运行。
- 根文件系统只读时挂载 `/tmp` 与 `/app/data`。
- 限制容器能力。
- 固定镜像版本，不使用 `latest` 生产运行。
- 定期更新基础镜像与应用版本。

## 安全检查清单

- [ ] 管理员开启 TOTP
- [ ] HTTPS 与 HSTS 正常
- [ ] `DNSMGR_TRUST_PROXY` 只信任实际代理
- [ ] CORS 来源白名单最小化
- [ ] 旧版 API Key 已停用
- [ ] API Key 有作用域与到期时间
- [ ] 部署命令默认关闭
- [ ] 数据库账号非 root
- [ ] 数据目录权限正确
- [ ] 整站备份可恢复
- [ ] 备份密钥离线保存
- [ ] 通知测试通过
- [ ] 审计日志可查询
- [ ] 容器使用非 root 与固定版本
