# 缓存刷新与预热

缓存刷新让新内容立即生效。预热提前把常用资源回源到边缘节点。

## 手动刷新

1. 打开“CDN 管理 → 缓存刷新”。
2. 选择“URL 刷新”或“目录刷新”。
3. 每行填写一个地址。
4. 提交。

示例：

```text
https://www.example.com/index.html
https://www.example.com/style.css
```

目录刷新示例：

```text
https://www.example.com/images/
https://www.example.com/css/
```

提交后页面显示成功与失败数量。任务历史保存类型、服务商、状态、说明与时间。

## 手动预热

切换到“缓存预热”，每行填写一个 URL。预热适合大促、发版后常用页面或视频封面等资源。

预热会消耗厂商配额。大量 URL 建议分批提交。

## 任务历史

历史列表展示：

- 类型：URL 刷新、目录刷新、预热。
- 服务商。
- 状态。
- 说明。
- 时间。

任务详情可以查看失败原因。支持重试的厂商会在任务详情提供重试入口。

## 自动预热任务

1. 打开“CDN 管理 → 自动预热”。
2. 点击“添加任务”。
3. 填写任务名称。
4. 填写链接列表，每行一个 URL。
5. 选择操作类型：缓存预热或清除缓存。
6. 选择周期：每日定时或间隔执行。
7. 保存。

任务保存后可以立即执行、启停或删除。列表展示上次执行、下次执行、执行周期与状态。

## 执行结果

自动任务执行完成后会统计成功与失败数量。失败原因通常是 URL 不属于该账户、配额不足或厂商接口限流。

## 与发版配合

前端构建产物带内容哈希。发版后通常只需要刷新根路径 `/`。静态资源 URL 变化后会自动回源。详细策略见仓库 `deploy/CDN-CACHE.md`。

## 常见问题

### 刷新后仍是旧内容

- 浏览器本地缓存未过期。
- CDN 未遵循源站缓存头。
- 刷新任务仍在处理中。
- 源站返回了新的 `Cache-Control`，但边缘 TTL 未到。

### 预热失败

确认 URL 可公开访问、返回 200，且属于当前 CDN 账户。需要登录的页面不适合预热。

### 配额不足

查看厂商控制台的刷新与预热配额。减少 URL 数量或申请提升配额。
